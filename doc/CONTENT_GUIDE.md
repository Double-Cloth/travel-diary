# 内容维护指南

## 页面编辑器

扉页和足迹摘要分别统计全部日记引用的图片、视频数量；高级筛选中的数量仅统计当前筛选结果。按每篇日记的附件条目累计，同一文件被不同日记引用时分别计数。

通过 `npm start` 启动，在终端输出的 localhost 地址打开页面。进入扉页的「日记工具箱」，选择「新增旅行日记」；手机先点击「打开日记工具箱」。日记详情的记录管理菜单提供修改与删除入口。首次写入按提示两次输入相同的 6 位数字密码，之后验证密码即可操作。运行环境与认证限制见 [维护指南](MAINTENANCE.md#运行与写入环境)。

| 区域 | 用法 |
| --- | --- |
| 行程与地点 | 日期、国家 / 地区、目的地必填；旅行标识、行政区及地点类型可选。 |
| 旅行正文 | 标题必填；Markdown 源码与可编辑预览同步。 |
| 图片与视频 | 多选或拖放文件；已有文件与待上传文件在同类列表中统一排序，新文件标记「待上传」。点击缩略图或文件名打开查看器，支持切换、缩放、旋转、播放和下载。箭头可将新文件移到已有文件之间。勾选多项后可一起前移、后移或移除，全选入口随当前文件类型调整；移除后可在「待移除」中单项或批量恢复原顺序。所有变更保存后生效。 |
| 高级文件设置 | 默认折叠，按需自定义正文和媒体存储目录，或按行填写项目中已有的媒体文件名。增删文件名、调整行序会同步到上方列表；删掉的原有引用可在待移除区恢复。目录变更同步显示目标路径；开启真实文件同步时，保存前仍从原位置预览，关闭同步则预览新目录下的引用文件。 |

国家显示名称留空时使用目录名称。中国目的地支持省市区目录反查，例如「衡阳」补全「湖南省」；跨省重名且无法唯一判断时不强行填写。目录外地点参考历史记录和明确后缀。自动值随日期或地点更新，手工修改及导入的值不会被自动覆盖。

`trip_id` 用于把多篇日记归为同一次旅行，默认按日期和目的地生成小写拼音标识，也可选择最近 5 个已有行程。同一行程去过同一行政区的多个目的地时，沿用同一个标识，到访次数按旅行去重。未填写的旧记录各自作为独立行程；界面按日期为行程编号，不展示原始标识。

保存成功后重新读取数据与统计。保存失败保留表单；正文加载失败时禁止修改，但仍可删除索引记录。删除先确认不可撤销的风险，再验证密码；只移除索引和正文，保留媒体文件。浏览器修改会比较打开编辑器时的元数据与正文：其他窗口或外部文件已更新时拒绝覆盖，应先导出草稿，刷新并重新打开记录后合并修改。

修改日记时，「保存时同步删除、移动真实文件」默认开启，关闭后仅更新引用并保留原文件。保存前的确认窗口直接展示受影响文件的缩略图，区分「将删除」与「将移动」，移动项注明目标路径。点击缩略图或文件名可核对图片、视频；关闭查看器返回确认，选择「返回编辑」保留草稿，不执行保存或删除。

## 正文与草稿

| 操作 | 行为 |
| --- | --- |
| 源码 | 编辑 Markdown，第一行一级标题与标题字段同步。 |
| 预览 | 直接编辑渲染文字；支持标题、段落、粗体、斜体和列表，粘贴按纯文本插入。 |
| 导出草稿 | ZIP 中的 `draft.json` 保存字段，待上传图片与视频放在 `media/`。 |
| 导入草稿 | 读取 ZIP 或旧版 JSON 后填入表单，核对后另行保存。 |
| 清空编辑器 | 确认后清除表单及待保存媒体，不删除磁盘上的记录。 |

预览修改会按支持的结构重新生成 Markdown，可能规范化空行与格式标记。表格、代码块、嵌套列表等未支持的结构应在源码中编辑。方向键、Home / End 可切换正文标签。

当前草稿格式为 `travel-diary-draft-v4`，ZIP 封装为 `travel-diary-draft-archive-v2`；兼容 v1 至 v3 JSON 和旧版 `photos/` ZIP。草稿同时保存新旧媒体的混合顺序；旧草稿未指定顺序时，已有文件在新增文件之前。已有项目媒体仍按原路径引用，草稿不能代替完整数据备份，`draft.json` 也不能替换旅行索引。修改模式下导入草稿仍然修改当前记录，保存前核对窗口标题。

文件列表有内容时才显示多选入口；仅有图片或视频时提供对应类型的全选，两者都有时可全选文件。抓住文件操作区的六点手柄可上下拖动排序；选中两项及以上时显示「拖动所选」手柄，也可抓住所选文件的手柄一起拖动。组内保持原有相对顺序，图片、视频仍分别排序。拖到列表边缘会自动滚动，松手后更新顺序；按 Escape、失去窗口焦点或触摸取消时保持原顺序。聚焦手柄后可用上下方向键调整，也可继续使用原有箭头。选中后显示批量移动和移除操作，边界处不能继续移动。待移除区可独立多选并恢复，恢复后保留原有混合顺序；未选中时只显示全选入口，全部恢复后整个区域隐藏。

未保存内容只在当前页面内存中保留。关闭后重开同一记录可续写，切换记录先确认丢弃风险，再验证密码；取消风险提示或密码验证均保留原草稿。刷新或离开页面前保存或导出。导入另一份草稿前，先导出当前内容，再清空编辑器。

## 文件路径与媒体

正文默认路径为 `data/travel-diary/YYYY/YYYY-MM-DD-pinyin.md`。例如「苏州市」生成 `data/travel-diary/2026/2026-09-11-suzhou.md`。自定义路径必须保持年份目录和日期前缀与记录日期一致；修改日期时同步调整路径，或留空重新生成。路径只允许规定的 ASCII 文件名，不允许穿越目录、系统保留名或符号链接。

新媒体分别写入 `data/photos/pinyin/` 和 `data/videos/pinyin/`。文件名转为小写、无声调拼音，按实际文件格式确定扩展名；本次列表重名追加序号，磁盘上的不同文件不被覆盖。原始媒体字节保留，不压缩或裁剪。已有媒体可引用多级目录，列表中的值为文件名；同类新媒体加入时，已有文件按需复制到目的地目录，来源保留；展示顺序按编辑器中的同类文件列表保存，可自由交错排列新旧文件。

修改日记时，「保存时同步删除、移动真实文件」默认勾选。保存后，从已有媒体列表移除的文件会同步删除，更改媒体目录会搬移保留的文件；清空的媒体目录及其空父目录也会删除，保留 `data/photos/` 和 `data/videos/` 根目录。其他日记仍在引用的文件和未列入原记录的文件会保留。取消勾选后，仅更新已有媒体引用，原文件保留且不搬移，目标目录中的文件需自行准备；新上传的媒体仍正常写入。调整展示顺序或移除尚未保存的上传文件不会删除原始文件。保存涉及移除或搬移原媒体时，先展示文件变更确认，按删除和移动分组列出缩略图，点击缩略图或文件名在媒体查看器中核对原文件；移动的文件会显示新路径，共享引用的文件不列入清单；选择「返回编辑」后保留编辑内容，不上传或写入文件。同步操作与本次记录保存一起提交，保存失败会恢复暂存的原文件。服务不支持真实媒体同步时会中止保存并提示重启服务，避免只更新引用。

| 限制 | 上限 |
| --- | --- |
| 单行字段 / 正文 | 200 / 100000 字符 |
| 已有图片列表 / 视频列表 | 各 1000 项，每个文件名 200 字符 |
| JPEG、PNG、GIF、WebP 图片 | 每张 1 GiB |
| MP4、M4V、MOV、WebM、Ogg 视频 | 每个 32 GiB |
| ZIP 草稿导入 | 100 GiB + 16 MiB，内含媒体仍受单文件与合计限制 |
| 本次待保存的新媒体 | 合计 100 GiB；以原始字节 ZIP 提交，请求上限 100 GiB + 16 MiB |

大小限制集中在 `js/file-limits.mjs`，编辑器、草稿解析和服务端共用。新媒体保留原始 File/Blob，只读取文件头识别格式；草稿 ZIP 使用 ZIP64，按 1 MiB 分块计算 CRC32，组合文件引用与小头部，不创建整段媒体数组。导入草稿随机读取目录、分块校验媒体并保留 Blob 切片；打包显示进度，未改变的媒体校验结果可复用。旧 JSON 草稿（文件上限 511 MiB）和 JSON 写入仍兼容，但受运行时字符串长度限制，大媒体请使用 ZIP。

保存失败清理本次创建的文件和空目录。新增请求结果不确定时可用原草稿重试，同路径、元数据及正文完全一致时识别为已保存；修改或删除结果不确定时先刷新核对。

## 元数据与手工维护

`data/travel_data.json` 为数组，每项对应一篇日记，空档案使用 `[]`。日记标题从 Markdown 的一级标题读取，不单独写入索引。

| 字段 | 类型 | 必需 | 说明 |
| --- | --- | --- | --- |
| `date` | string | 是 | 有效日期，格式 `YYYY-MM-DD`。 |
| `country_code` | string | 是 | 国家目录中的 ISO alpha-2 代码，如 `CN`、`JP`。 |
| `country` | string | 是 | 面向读者显示的国家 / 地区名称。 |
| `admin_area` | string | 否 | 州、省、都道府县等一级行政区，城市国家可省略。 |
| `admin_area_type` | string | 否 | 行政区类型覆盖值。 |
| `locality` | string | 是 | 城市、村镇、岛屿、景区等目的地。 |
| `locality_type` | string | 否 | 目的地类型。 |
| `trip_id` | string | 否 | 同一次旅行各篇沿用同一标识。 |
| `desc_md` | string | 是 | 相对项目根目录的 Markdown 路径。 |
| `photo_folder` / `video_folder` | string | 否 | `data/photos/` / `data/videos/` 下的目录。 |
| `photos` / `videos` | string[] | 否 | 对应目录中的文件名，按展示顺序排列。 |

```json
{
  "date": "2026-07-11",
  "country": "中国",
  "country_code": "CN",
  "admin_area": "江苏省",
  "locality": "苏州市",
  "trip_id": "2026-07-11-suzhou",
  "desc_md": "data/travel-diary/2026/2026-07-11-suzhou.md",
  "photo_folder": "data/photos/suzhou",
  "photos": ["canal.jpg", "garden.jpg"]
}
```

手工新增时先创建 Markdown，再添加索引项，运行测试并检查页面；修改正在打开的记录后，刷新编辑器再继续编辑。文件大小写必须与引用一致。旧内容的 `province` / `city` 和旧路由仍可读取，新内容统一用 `admin_area` / `locality`。其他国家的行政区标签由国家目录决定，不需要假设所有国家都有省。

## 个人资料与完整备份

扉页工具箱可修改头像与署名。头像输入支持 JPEG、PNG、GIF、WebP，源文件不超过 96 MiB，转换为最长边 1024 像素的 PNG，保存到 `data/profile/profile-picture.png`。署名最多 24 个 Unicode 字符，保存到 `data/profile/owner-name.txt`，缺失或空白时显示「山川过客」。

「数据备份」操作需要可写服务和认证：

| 操作 | 范围与结果 |
| --- | --- |
| 导出全部数据 | 打包完整 `data/` 与 `.secrets/auth.json`，包括未引用的普通媒体文件。 |
| 导入全部数据 | 先确认不可撤销的覆盖风险，再验证当前密码、选择并核对备份；含认证配置时再验证备份密码，校验成功后覆盖数据并恢复备份密码；旧备份没有认证配置时明确提示无法验证备份密码并保留当前密码；成功后注销所有旧会话。 |
| 清空全部数据 | 先确认不可撤销的风险，再验证密码并删除记录、正文、媒体、自定义头像和署名，重建空档案；保留当前密码。 |

网页完整备份导入上限 100 GiB，支持本应用导出的未压缩 ZIP / ZIP64，包括单个超过 4 GiB 的视频；不支持加密 ZIP、压缩条目或分卷。备份必须含合法索引及被引用的 UTF-8 正文，最多 10000 条记录。可选字段允许省略，错误类型仍被拒绝。媒体引用缺失可恢复，页面显示缺失状态，不阻断其他内容；无效路径不能导入。旧 `data/password.json` 被忽略。

完整备份导出逐文件读取并发送；导入先将请求暂存到磁盘，再分块校验、写入暂存目录，全部验证通过后替换当前数据。内存不随媒体总大小增长；磁盘需同时容纳当前数据、上传 ZIP 和解包后的新数据。

备份没有加密，包含认证哈希，应保持私密。大于网页导入上限的备份按 [文件系统恢复流程](MAINTENANCE.md#备份与恢复) 处理。静态部署仅提供只读编辑器和草稿导入导出，不提供保存、删除或全部数据操作；网络失败和 API 异常不会被当作只读环境放行。

## 发布自己的内容

替换 `data/` 中的个人资料、索引、正文和媒体即可复用，无需删减国家目录或更换通用设计资产。删除不用的示例文件，避免残留内容公开发布。保存到本机与发布到线上是两个步骤：当前媒体目录被 Git 忽略，普通提交不会自动携带新媒体，发布方式见 [维护指南](MAINTENANCE.md#静态发布)。
