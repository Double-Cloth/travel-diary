# 内容维护指南

## 页面编辑器

通过 `npm start` 启动，在终端输出的 localhost 地址打开页面。进入扉页的「日记工具箱」，选择「新增旅行日记」；手机先点击「打开日记工具箱」。日记详情的记录管理菜单提供修改与删除入口。首次写入按提示两次输入相同的 6 位数字密码，之后验证密码即可操作。运行环境与认证限制见 [维护指南](MAINTENANCE.md#运行与写入环境)。

| 区域 | 用法 |
| --- | --- |
| 行程与地点 | 日期、国家 / 地区、目的地必填；旅行标识、行政区及地点类型可选。 |
| 旅行正文 | 标题必填；Markdown 源码与可编辑预览同步。 |
| 图片与视频 | 多选或拖放文件，查看预览、调整顺序、移除待保存媒体。 |
| 文件设置 | 自定义正文路径，或引用项目中已有的图片、视频。 |

国家显示名称留空时使用目录名称。中国目的地支持省市区目录反查，例如「衡阳」补全「湖南省」；跨省重名且无法唯一判断时不强行填写。目录外地点参考历史记录和明确后缀。自动值随日期或地点更新，手工修改及导入的值不会被自动覆盖。

`trip_id` 用于把多篇日记归为同一次旅行，默认按日期和目的地生成小写拼音标识，也可选择最近 5 个已有行程。同一行程去过同一行政区的多个目的地时，沿用同一个标识，到访次数按旅行去重。未填写的旧记录各自作为独立行程；界面按日期为行程编号，不展示原始标识。

保存成功后重新读取数据与统计。保存失败保留表单；正文加载失败时禁止修改，但仍可删除索引记录。删除需确认，只移除索引和正文，保留媒体文件。浏览器修改会比较打开编辑器时的元数据与正文：其他窗口或外部文件已更新时拒绝覆盖，应先导出草稿，刷新并重新打开记录后合并修改。

## 正文与草稿

| 操作 | 行为 |
| --- | --- |
| 源码 | 编辑 Markdown，第一行一级标题与标题字段同步。 |
| 预览 | 直接编辑渲染文字；支持标题、段落、粗体、斜体和列表，粘贴按纯文本插入。 |
| 导出草稿 | ZIP 中的 `draft.json` 保存字段，待上传图片与视频放在 `media/`。 |
| 导入草稿 | 读取 ZIP 或旧版 JSON 后填入表单，核对后另行保存。 |
| 清空编辑器 | 确认后清除表单及待保存媒体，不删除磁盘上的记录。 |

预览修改会按支持的结构重新生成 Markdown，可能规范化空行与格式标记。表格、代码块、嵌套列表等未支持的结构应在源码中编辑。方向键、Home / End 可切换正文标签。

当前草稿格式为 `travel-diary-draft-v4`，ZIP 封装为 `travel-diary-draft-archive-v2`；兼容 v1 至 v3 JSON 和旧版 `photos/` ZIP。已有项目媒体仍按原路径引用，草稿不能代替完整数据备份，`draft.json` 也不能替换旅行索引。修改模式下导入草稿仍然修改当前记录，保存前核对窗口标题。

未保存内容只在当前页面内存中保留。关闭后重开同一记录可续写，切换记录需要确认丢弃；刷新或离开页面前保存或导出。导入另一份草稿前，先导出当前内容，再清空编辑器。

## 文件路径与媒体

正文默认路径为 `data/travel-diary/YYYY/YYYY-MM-DD-pinyin.md`。例如「苏州市」生成 `data/travel-diary/2026/2026-09-11-suzhou.md`。自定义路径必须保持年份目录和日期前缀与记录日期一致；修改日期时同步调整路径，或留空重新生成。路径只允许规定的 ASCII 文件名，不允许穿越目录、系统保留名或符号链接。

新媒体分别写入 `data/photos/pinyin/` 和 `data/videos/pinyin/`。文件名转为小写、无声调拼音，按实际文件格式确定扩展名；本次列表重名追加序号，磁盘上的不同文件不被覆盖。原始媒体字节保留，不压缩或裁剪。已有媒体可引用多级目录，列表中的值为文件名；同类新媒体加入时，已有文件按需复制到目的地目录，来源保留，顺序在新媒体之前。

| 限制 | 上限 |
| --- | --- |
| 单行字段 / 正文 | 200 / 100000 字符 |
| 已有图片列表 / 视频列表 | 各 1000 项，每个文件名 200 字符 |
| JPEG、PNG、GIF、WebP 图片 | 每张 96 MiB |
| MP4、M4V、MOV、WebM、Ogg 视频 | 每个 512 MiB |
| 本次待保存的新媒体 | 合计 512 MiB；Base64 JSON 请求不超过 768 MiB |

保存失败清理本次创建的文件和空目录。新增请求结果不确定时可用原草稿重试，同路径、元数据及正文完全一致时识别为已保存；修改或删除结果不确定时先刷新核对。

## 元数据与手工维护

`data/travel_data.json` 为数组，每项对应一篇日记，空档案使用 `[]`。日记标题从 Markdown 的一级标题读取，不单独写入索引。

| 字段 | 类型 | 必需 | 说明 |
| --- | --- | --- | --- |
| `date` | string | 是 | 有效日期，格式 `YYYY-MM-DD`。 |
| `country_code` | string | 是 | 国家目录中的 ISO alpha-2 代码，如 `CN`、`JP`。 |
| `country` | string | 是 | 面向读者显示的国家 / 地区名称。 |
| `admin_area` | string | 否 | 州、省、都道府县等一级行政区，城市国家可省略。 |
| `admin_area_type` | string | 否 | 行政区类型覆盖值。 |
| `locality` | string | 是 | 城市、村镇、岛屿、景区等目的地。 |
| `locality_type` | string | 否 | 目的地类型。 |
| `trip_id` | string | 否 | 同一次旅行各篇沿用同一标识。 |
| `desc_md` | string | 是 | 相对项目根目录的 Markdown 路径。 |
| `photo_folder` / `video_folder` | string | 否 | `data/photos/` / `data/videos/` 下的目录。 |
| `photos` / `videos` | string[] | 否 | 对应目录中的文件名，按展示顺序排列。 |

```json
{
  "date": "2026-07-11",
  "country": "中国",
  "country_code": "CN",
  "admin_area": "江苏省",
  "locality": "苏州市",
  "trip_id": "2026-07-11-suzhou",
  "desc_md": "data/travel-diary/2026/2026-07-11-suzhou.md",
  "photo_folder": "data/photos/suzhou",
  "photos": ["canal.jpg", "garden.jpg"]
}
```

手工新增时先创建 Markdown，再添加索引项，运行测试并检查页面；修改正在打开的记录后，刷新编辑器再继续编辑。文件大小写必须与引用一致。旧内容的 `province` / `city` 和旧路由仍可读取，新内容统一用 `admin_area` / `locality`。其他国家的行政区标签由国家目录决定，不需要假设所有国家都有省。

## 个人资料与完整备份

扉页工具箱可修改头像与署名。头像输入支持 JPEG、PNG、GIF、WebP，源文件不超过 12 MiB，转换为最长边 1024 像素的 PNG，保存到 `data/profile/profile-picture.png`。署名最多 24 个 Unicode 字符，保存到 `data/profile/owner-name.txt`，缺失或空白时显示「山川过客」。

「数据备份」操作需要可写服务和认证：

| 操作 | 范围与结果 |
| --- | --- |
| 导出全部数据 | 打包完整 `data/` 与 `.secrets/auth.json`，包括未引用的普通媒体文件。 |
| 导入全部数据 | 校验后替换当前数据；含认证配置时恢复备份密码，不含时保留当前密码；成功后注销所有旧会话。 |
| 清空全部数据 | 二次确认后删除记录、正文、媒体、自定义头像和署名，重建空档案；保留当前密码。 |

网页导入上限 256 MiB，支持本应用导出的未压缩 ZIP；不支持加密 ZIP、压缩条目或分卷。备份必须含合法索引及被引用的 UTF-8 正文，最多 10000 条记录。可选字段允许省略，错误类型仍被拒绝。媒体引用缺失可恢复，页面显示缺失状态，不阻断其他内容；无效路径不能导入。旧 `data/password.json` 被忽略。

备份没有加密，包含认证哈希，应保持私密。大于网页导入上限的备份按 [文件系统恢复流程](MAINTENANCE.md#备份与恢复) 处理。静态部署仅提供只读编辑器和草稿导入导出，不提供保存、删除或全部数据操作；网络失败和 API 异常不会被当作只读环境放行。

## 发布自己的内容

替换 `data/` 中的个人资料、索引、正文和媒体即可复用，无需删减国家目录或更换通用设计资产。删除不用的示例文件，避免残留内容公开发布。保存到本机与发布到线上是两个步骤：当前媒体目录被 Git 忽略，普通提交不会自动携带新媒体，发布方式见 [维护指南](MAINTENANCE.md#静态发布)。
