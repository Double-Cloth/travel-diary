# 维护与发布指南

全部运维命令集中在 [README](../README.md)。以下说明环境、部署与恢复行为。

## 运行与写入环境

使用 Node.js 20 或更新版本；普通启动无需安装 npm 依赖。服务器默认绑定 `127.0.0.1:9000`，端口占用时尝试后续端口，以终端输出为准。不会自动打开浏览器。不要用 `file://` 打开模块入口。

缺少数据结构时启动会补齐空索引、日记、图片、视频及资料目录和默认头像，不覆盖已有文件；缺少 `.secrets/` 时创建目录，密码在首次本机写入时设置。

| 环境 | 浏览 | 写入与管理 |
| --- | --- | --- |
| 默认 local 模式的 localhost 页面 | 支持 | 认证后支持全部功能。 |
| `--network`、local 写入模式的远程地址 | 支持 | 拒绝远程认证和写入；监听范围不会自动放开权限。 |
| remote 模式的白名单 HTTPS 站点 | 支持 | 认证后支持；启动前须已在本机设置密码。 |
| GitHub Pages / 通用静态托管 | 支持 | 支持只读编辑器、草稿及全部/部分记录备份导出；不支持服务器保存、导入或清空。 |

所有页面资源、字体、拼音和目录随项目分发，本机运行无需外部 CDN。线上没有 Service Worker，断网首次访问或刷新不保证可用。更新浏览器资源后刷新页面；修改 Node 服务端代码后须重启原服务，再核对终端端口，避免新旧进程同时运行导致访问旧实现。静态发布更换带版本参数的资源时同步更新入口、模块及 CSS 分片的引用版本。

## 认证与部署边界

密码为 6 位数字，首次设置及换密拒绝重复、连续和常见弱组合。扉页「访问安全」可验证当前密码后换密；配置损坏或强制恢复才使用交互式 `auth:set`。仅换密无需重启。

服务端保存随机盐与 scrypt 哈希。任意来源合计连续失败 5 次后限速 15 分钟；同一浏览器会话内首次验证后最长 8 小时免重复验证，刷新页面保留登录状态，重复操作不延长有效期；浏览器会话结束、到期或服务器重启后需重新验证。换密注销其他旧会话并为当前页面签发新会话，数据导入成功则注销所有旧会话。Cookie 为 `HttpOnly`、`SameSite=Strict`，remote 模式增加 `Secure`。

remote 模式仅接受明确配置的完整 HTTPS Origin，允许多次指定；请求 Host 必须与来源对应。反向代理须保留外部 Host 和 Origin，应用不信任 `X-Forwarded-*`。代理与 Node 在同机时保持 `--local`，仅在确有跨主机连接需求时用 `--network`。公网写入在 HTTPS 之外还应有独立身份认证、VPN 或 Zero Trust。

`.secrets/auth.json` 仅保存在本机，整个 `.secrets/` 由 Git 忽略；首次检出后按页面提示设密，迁移已有站点时通过授权备份或本机复制恢复配置。本项目早期提交曾跟踪认证哈希，停止跟踪不会删除历史；六位数字的哈希不能抵御离线穷举，若历史仓库或备份曾公开，应清理相关历史并换密。完整备份仍包含认证配置，须妥善保管。密码只保护写入，日记和媒体阅读权限由部署层控制。

Node 静态服务拒绝任意层级的隐藏路径及 `.zip`、`.bak`、`.tmp` 文件，并拦截根目录的 `dist/`、`build/`、`output/`、`tmp/`、`temp/`、`node_modules/`、`_site/`、`coverage/`；真实路径也执行同样检查，目录别名不能绕过。`.cache/media-previews/` 仅开放专用缩略图接口，完整备份通过认证 API 下载。其他静态服务器及反向代理也必须排除秘密、备份、缓存和临时目录，不能直接将项目根目录全部公开。

## 备份与恢复

静态页面的全部、部分记录及行程导出直接在浏览器打包，无需密码。全部导出包含当前索引、被引用的正文和附件，以及已发布的头像与署名；部分导出仅包含所选日记及附件。静态服务无法枚举目录，因此不包含未引用文件、认证配置或回收站，也不维护服务端增量比较基准。正文缺失时停止导出；附件返回 404 时保留索引引用并明确提示缺失数，其他读取错误中止。打包复用 ZIP64 与分块 CRC32，但浏览器仍需下载并保留文件 Blob，超大档案建议从本机动态服务或命令行导出。静态备份可在动态服务中导入，保留目标站点当前密码。

动态服务网页「导出全部数据」与命令行备份都包含 `data/` 和有效 `.secrets/auth.json`，默认命令行输出在被 Git 忽略的 `dist/`。命令行目标必须以 `.zip` 结尾，且不能位于 `data/`、`.secrets/` 或 `.cache/`，包含指向这些目录的别名；建议使用默认目录或项目外的受保护目录。导出先写独占临时文件，成功后替换目标，失败清理临时文件并释放锁。导出期间使用统一数据锁，不要同时运行保存或导入。网页与命令行导出均使用 ZIP64，逐文件按 1 MiB 分块读取、计算 CRC32，并遵循输出背压，只保留小型目录信息。HEAD 请求仅准备文件列表和下载长度，不扫描媒体。网页导入先将请求流写入根目录 `.travel-upload-*.tmp`，再随机读取 ZIP 目录并分块校验、解包到暂存目录；失败或断线清理临时文件，全部校验成功才替换数据。记录保存、已有媒体搬运和重试内容校验也采用分块处理，不再整段读取视频。

大备份需要足够磁盘空间：导入期间同时保留现有数据、上传 ZIP 和解包后的新数据。例如导入 60 GiB 未压缩备份，除现有数据外应至少预留约 120 GiB，并留出文件系统余量。导出期间保持数据锁直到下载完成或断线；慢下载期间其他写入会提示操作冲突。浏览器 File/Blob 实现、磁盘读写及 CRC32 运算仍会影响耗时。

记录保存和网页完整备份导入的请求超时均为 8 小时；使用反向代理时需同步放宽请求体上限、上传超时与下载读取超时，记录 ZIP 至少允许 100 GiB + 16 MiB，完整备份至少允许 100 GiB。会话最长仍为 8 小时，长任务建议重新验证后立即开始。JSON 与 ZIP 保存都会在数据锁内及提交前重新验证会话；上传期间注销、换密或会话过期后拒绝写入，保留原内容并回滚暂存。首次设密和登录对非法 JSON 返回 400，对声明或实际超限的请求返回 413；分块上传超限也保留明确的 HTTP 错误响应。旧 JSON 接口与草稿仍受字符串上限约束，使用 ZIP / ZIP64 处理大型媒体。

网页导入最多 100 GiB，接受本应用导出的未压缩 ZIP / ZIP64，兼容旧 ZIP。单个视频最多 32 GiB，单张图片最多 1 GiB，单次新媒体合计最多 100 GiB。先确认数据替换范围，再复用有效会话或验证当前密码、选择并核对备份；备份认证配置与当前一致时复用会话，不一致时再输入导出该备份时的密码，服务端验证备份密码、索引、正文、路径及认证配置后才替换数据并恢复备份密码。旧备份不含认证文件时会提示无法验证备份密码，导入后保留当前密码。任一密码错误均不覆盖数据；导入密码累计失败 5 次后限速 15 分钟，重新登录不能清除该计数。导入后重新登录。清空保留密码，全部个人内容留存在回收站；导入覆盖前也保存原数据。

无法网页导入的大备份，或进程异常后的目录恢复：

1. 停止所有本项目服务，另行复制现有 `data/` 和 `.secrets/`，保留回退副本。
2. 将可信备份解压到独立目录，核对索引、被引用正文和媒体路径；若含认证配置，确认准备恢复的是对应密码。
3. 用完整备份的 `data/` 替换当前目录；含 `.secrets/auth.json` 时一并恢复，没有时保留现有配置。不要把 ZIP 内未经核对的任意路径直接解压覆盖项目。
4. 重新启动，检查各页内容及登录，确认成功后再清理回退副本。

## 静态发布

### 媒体预览

媒体预览无需任何额外依赖或生成命令。列表进入视口时先读取缓存，缓存缺失时由浏览器原生 Canvas 自动缩放至最长边 640px、以 JPEG 质量 0.78 压缩；视频解码首帧作为封面。首次生成必须读取一次原文件，之后列表只加载预览。关闭或切换查看器仍停止旧视频读取。浏览器不支持的编码保留占位，可点击查看或下载原文件。

本地服务自动接收同源浏览器生成的预览并保存到 `.cache/media-previews/`，不修改原始图片、视频，不放进 `data/`。服务检查源文件大小、mtime、ctime，变化后自动重建；缓存元数据损坏、元数据超过 4 KiB，或预览失去有效 JPEG 头与尺寸时按缓存未命中处理，浏览器重新生成。媒体预览缓存被 Git 忽略，不进入完整备份，可随时清理并在下次浏览时自动重建；同处 `.cache/` 的回收站不可当作预览缓存删除；`.cache` 只有媒体预览专用接口可访问，其他文件继续禁止下载。

使用 [README 中的缓存清理命令](../README.md#媒体预览与缓存) 清理项目 `.cache/` 下的缓存，但保留 `.cache/recycle-bin/` 回收站，也可指定目标项目目录。目录不存在时正常结束；拒绝将符号链接或 junction 作为缓存根目录。不删除 `data/`、`.secrets/` 或浏览器 Cache Storage；清理后缩略图在下次浏览时自动重建，也可运行批量生成命令。为避免与正在保存的缩略图互相干扰，建议停止批量生成任务并关闭站点页面后清理。

需要提前生成全部缩略图时，使用 [README 中的批量预览命令](../README.md#媒体预览与缓存)。命令读取索引、去重媒体路径，启动临时回环服务并调用本机已有的 Edge / Chrome 无头浏览器，复用相同 Canvas 压缩与缓存校验；完成后关闭服务与浏览器。有效缓存跳过，缺失或过期缓存重新生成，失败项继续处理并在末尾汇总，存在失败时退出码为 1。无需 npm 或 FFmpeg 依赖，也无需先启动站点。浏览器未自动找到时可指定可执行文件，也可指定含 `data/travel_data.json` 的目标项目目录，参数用法集中在 README。视频支持范围取决于所选浏览器，无法解码时报告失败并保留原文件。

GitHub Pages 等静态托管不能写服务器文件系统，自动使用浏览器 Cache Storage 保存缩略图，缓存键对应 `.cache/media-previews/` 路径；通过原文件 HEAD 返回的 ETag、Last-Modified 和 Content-Length 区分版本。静态服务器应提供 ETag 或 Last-Modified，以识别同大小文件替换。不同浏览器分别生成，清理站点存储后会重新生成；浏览器禁用缓存、非安全上下文或缓存配额不足时只能复用本次已解码的预览。发布工作流无需安装媒体工具或预生成缩略图。

### 发布流程

GitHub Pages 工作流在 push 或手动触发时运行：Node.js 20、Python 字体工具、完整字体构建、全部测试，然后发布 `index.html`、`api/`、`assets/`、`css/`、`doc/`、`js/` 和 `data/`。当前没有限制 push 分支；调整触发范围应修改工作流。构建会补齐缺少的空档案和头像，移除发布物中的 TTF 源文件，保留 WOFF2。

发布物不包含 `.secrets/`、完整备份 ZIP 或服务端运行进程。`api/travel-records` 是静态只读标记；发布到其他静态平台时也应保留它，同时排除秘密及运行临时目录。

`data/photos/` 与 `data/videos/` 默认被 Git 忽略，GitHub Actions 只能获取已跟踪文件。要将媒体公开发布，可显式选择需要的文件，命令见 [README](../README.md#部署与备份)，再与对应索引、正文一起提交；也可由自己的部署流程提供同路径媒体。发布前检查隐私、媒体大小及仓库容量，不要误把「本机保存成功」当成「线上已更新」。

发布前执行 [README 中的测试与补丁检查](../README.md#启动与检查)，浏览封面、扉页、路径、归档、地点、日记与附件页；至少覆盖窄手机、平板、桌面和横屏。重点检查空数据、筛选无结果、长文本、缺失媒体、加载失败、键盘操作和只读编辑器。涉及写入时用临时数据目录验证，避免改动个人档案。

## 写入故障恢复

| 现象 | 处理 |
| --- | --- |
| 索引加载失败 | 核对 JSON 数组、有效日期、目录权限及网络；重试入口应可见。 |
| 单篇正文失败 | 核对 `desc_md` 大小写及文件存在性；其他记录仍可浏览。 |
| 地点候选未加载 | 检查两个 `assets/catalogs/` 文件和请求；失败不会留下半初始化目录，可再次打开编辑器。 |
| 未登录打开写入入口 | `GET /api/travel-records` 能力探测应返回 200 和 `authenticated: false`，随后显示密码窗口；实际未授权写入仍返回 401。若探测仍为 401，先确认已重启并访问更新后的服务。 |
| 403 / 无写入能力 | 核对访问地址、write mode、完整 HTTPS Origin、Host 和登录，不靠 `--network` 放开权限。 |
| 修改提示记录已变化 | 先导出草稿，刷新重开，合并其他窗口或外部文件的更新。 |
| 已保存但重读失败 | 数据已经落盘，手动刷新核对，无需直接重复原操作。 |
| 导入失败 | 核对 100 GiB 上限、可用磁盘空间、未压缩 ZIP / ZIP64、索引及 UTF-8 正文；损坏目录或路径会被拒绝。 |
| 导入后登录失败 | 含认证文件时使用备份中的密码；不含时使用当前密码，旧会话已注销。 |
| 媒体不显示 | 检查拼接路径、文件名大小写及部署是否包含被忽略的媒体；缺失文件不阻断日记。 |
| 字体或背景缺失 | 检查 CSS 相对引用及部署文件；完整字体应随仓库提供。 |
| 数据锁长期占用 | 先确认是否仍有活动操作；异常退出后按下列步骤恢复。 |

异常退出时，先停止全部服务并备份。核对根目录 `.travel-upload-*.tmp`、`.travel-data.lock`、`.travel-data-import-*`、`.travel-data-clear-*`、`.travel-data-backup-*`、`.travel-secrets-backup-*`，以及 `data/` 内的 `.travel-write-*.tmp`、日记临时文件和 `.bak`。备份目录按数据及认证配置成对核对，临时正文先与索引比对；不要删除唯一的内容副本。确认无活动操作后才移除遗留锁，恢复后检查索引、正文、媒体与登录。

## 测试与资源更新

[全部测试命令](../README.md#启动与检查) 使用 Node 内置测试运行器，不需安装测试依赖。覆盖路由、统计、目录、Markdown、草稿、媒体、认证、来源策略、写入冲突、ZIP / ZIP64、40 GiB 偏移、分块背压、上传中断清理和失败回滚，也覆盖分块 JSON 超限、上传期间注销、私有路径别名、备份输出保护、损坏预览恢复，以及内存和磁盘字节源的非法切片。写入类测试使用临时目录，不修改仓库个人数据；浏览器辅助加载器不改变项目模块配置。静态断言与单元测试不能替代真实浏览器布局和完整交互验证。

清理旧实现后按现有入口回归：未登录从扉页工具箱打开新增日记，应显示密码窗口且能力探测不产生控制台错误；直接进入扉页或日记页不应请求封面位图或出现未使用预加载警告。桌面与手机分别检查目录搜索到日记、归档到地点、夹层打开与 Escape 关闭、图片缩放和视频播放，再核对控制台及资源请求。封面开合与现有对话框共用纸面样式仍需保留，不以删除旧功能测试代替现有功能回归。

更新国家或中国省市区数据时，先调整对应脚本中的固定版本，运行生成命令，核对名称、代码及数量变化，再测试并检查筛选与省份反查。字体源文件更新后重新生成完整 WOFF2。来源与资源清理规则见 [资产管理规范](ASSET_MANAGEMENT.md)。
