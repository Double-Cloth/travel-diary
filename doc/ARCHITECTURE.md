# 架构说明

## 运行入口与页面

前端为原生 ES modules，入口是 `index.html`、`js/app.js` 和 `css/journal.css`。浏览不依赖 Node API；可选 `js/server.js` 提供静态资源、认证、记录写入和完整备份。项目没有运行时 npm 依赖，也不需要前端构建。

| Hash 路由 | 页面与职责 |
| --- | --- |
| `#cover` | 合盖封面与开本入口。 |
| `#preface` | 扉页、个人资料、日记工具箱、备份及访问安全。 |
| `#ledger` | 旅行路径、记录列表、搜索和多级筛选。 |
| `#archive` | 日记归档及地点统计。 |
| `#place?country=CN&area=...` | 地点档案、相关日记及汇总媒体预览，参数按 URL 编码。 |
| `#entry?id=...` | 日记详情、相邻篇目与记录管理。 |
| `#photos?id=...` | 当前日记的图片、视频附件。 |
| `#photos?country=CN&area=...` | 对应地点全部日记的图片、视频附件，按日记日期和标题分组，可附加 `locality` 限定目的地。 |

筛选与页面状态由 `app.js` 统一管理，旧 `province` / `city` 参数会转换为当前地点模型。不存在的记录、空列表、正文缺失和加载失败各自呈现可恢复状态；加载失败解除封面模式，使错误和重试入口可见。

## 读取与浏览器交互

署名与档案独立并行加载；索引先校验，正文最多 8 个请求并发，单次请求超时为 20 秒。同轮加载共享相同路径的正文请求，每条记录独立解析，刷新时重新请求。正文允许浏览器缓存，结果保持索引顺序；404 等永久性响应及超时不立即重试，临时服务端错误和响应中断允许重试一次。单篇失败显示提示并保留其他记录及地点搜索，不让一篇文件拖垮全站。署名读取失败回退默认值，头像从 `data-src` 加载。封面图片由可见封面的 CSS 背景触发加载，不做全路由预加载，避免直接打开日记或扉页时出现未使用预加载资源的警告。

Markdown 使用应用支持的有限语法，输出经过 HTML 转义与链接过滤；预览复用相同解析器，编辑后通过受限 DOM 序列化生成 Markdown。新增格式必须同步考虑展示、编辑与安全过滤。

桌面采用双页分工及独立滚动；不超过 760px 时转为连续阅读，路径筛选、扉页工具箱和归档概览使用可开关夹层。长连续文字允许换行，窄屏及触摸设备放大控件点击范围，短横屏压缩媒体工具间距。夹层和媒体查看器锁定背景交互、约束 Tab 焦点，关闭查看器恢复触发按钮焦点。跳转链接聚焦内容区；修饰键点击路由链接保留浏览器原生行为。

自定义选择框以原生 `select` 为数据来源，同步禁用状态并跳过禁用选项；方向键及 Home / End 可导航，菜单按可见视口限制尺寸。菜单关闭后停止布局更新。

搜索更新保留原输入、光标与选区，Tab 离开后保持当前控件焦点；点击筛选同时纳入尚未到防抖期限的搜索内容，重绘后聚焦可见筛选按钮。无结果时提供清除条件的恢复入口。原生对话框打开时，媒体与夹层快捷键暂停；丢失指针捕获或窗口失焦会中止拖动，避免进度条保持在拖动状态。

连续导航时，正在播放的翻页保留当前曲面，以最多 160ms 加速落稳后衔接最新目标；落页期间的重复请求只保留最后一次。首帧播放前可直接替换，关闭或禁用动画时立即清理副本与回调，窗口尺寸变化时直接呈现待切换目标。启用 `prefers-reduced-motion` 时直接切换，动画期间背景内容使用 `inert` 防止穿透操作。

动画准备期间保留平面旧页覆盖，等待目标纸面背景、首屏可见图片解码和字体就绪后再生成目标副本，完成首帧绘制后交接曲面纸带；取消时一并清理资源等待与副本。资源失败或等待超过 2 秒时直接切换真实页面，避免动画中途补画或阻塞导航。桌面副本固定原页背景、内边距并沿用自定义滚动条槽宽，避免新路由样式或滚动条类型变化导致内容跳动。动画副本在深拷贝前裁去屏外记录内容，附件网格固定原尺寸且只保留可见子项；可见图片和视频冻结为最长边不超过 512px 的静态缩略图，避免每条卷曲纸带重复创建视频解码器或绘制原始大图。未解码或无法读取的媒体在动画中保留占位。预览行数同步及尺寸观察仅作用于真实左右页，跳过动画副本。

附件列表的图片和视频统一显示最长边不超过 640px 的 JPEG 预览，视频使用首帧封面。预览路径为 `.cache/media-previews/photos/.../原文件名.jpg` 或 `videos/.../原文件名.jpg`，保留原扩展名避免重名。`IntersectionObserver` 在进入视口后才读取缓存，缺失时通过浏览器原生图片、视频解码与 Canvas 自动压缩，最多同时处理两项，同一路径共享生成任务。首次生成需要读取一次原文件，此后列表只读取压缩预览；查看器仍使用当前项原文件，视频保留 Range 按需播放。编辑器与删除风险确认列表复用该流程，解码失败保留可点击占位。

Node 服务通过 `media-preview-store.js` 读写 `.cache/media-previews/`，不启动外部解码程序。缓存缺失返回 204 与源文件指纹，浏览器完成压缩后自动以同源 PUT 保存；服务校验路径、文件大小、JPEG 尺寸及源指纹，原文件变化则拒绝旧预览，后续自动重建。缓存读取支持 ETag，`.cache` 的其他内容禁止静态访问。预览缓存不属于个人数据，无需密码，只允许同源页面写入，不提供原文件写入能力。静态托管无法写服务器目录，自动改用 Cache Storage，并通过原文件 HEAD 的 ETag、Last-Modified、Content-Length 验证版本；不要求发布前生成。

## 样式结构

`journal.css` 按编号顺序加载 11 个同目录分片，后加载的规则可覆盖前者；CSS 资产统一以 `../assets/` 引用。

| 分片 | 范围 |
| --- | --- |
| `01-foundation`、`02-shell` | 字体、变量、基础可访问性、书脊与纸页外壳。 |
| `03-controls`、`04-ledger`、`05-archive-place` | 共用按钮、日记目录、归档及地点。 |
| `06-entry-sheet`、`07-responsive`、`08-custom-select` | 正文、事务对话框、基础适配和选择菜单。 |
| `09-book-experience`、`10-refined-ui`、`11-skeuomorphic-book` | 开合封面、视觉覆盖、拟物细节和最终屏幕适配。 |

改样式先确认实际生效的覆盖层，延续皮革、纸张、黄铜和手账排版。修改已带版本参数的浏览器资源时，同步入口和引用方的版本参数，避免静态托管沿用旧缓存。不要增加另一套页面入口或平行组件体系。旧首页的近期记录卡片、随机路线票据、旧日记详情弹层及配套动画、样式已移除，`#cover` 只保留实体封面，记录浏览统一从日记目录进入；`entry-sheet` 仍为现有编辑、认证和数据操作对话框提供共用纸面样式。

## 认证与写入

删除记录、清空数据、导入全部数据及切换记录丢弃未保存内容时，点击入口先确认危险操作，之后才探测服务、验证密码或选择文件。取消确认不会清除草稿或执行后续操作。

| API | 用途 |
| --- | --- |
| `/api/travel-auth`、`/api/travel-auth/setup` | 登录、换密、首次本机设密。 |
| `/api/travel-records` | 能力探测、创建、更新与删除。 |
| `/api/travel-profile` | 头像与署名写入。 |
| `/api/travel-data` | 完整备份导入导出与清空。 |

前端通过同源相对 URL 探测能力。静态发布物的 `api/travel-records` 提供 `travel-diary-static-v1` 标记，只有明确标记才打开免密码只读编辑器；404、超时、403 和异常响应均中止操作。动态能力 GET 在未登录或会话失效时返回 `200`、`authenticated: false`、空 `methods` 和 `AUTH_REQUIRED`，不泄露 token；正常打开密码窗口不会产生 `401` 控制台报错，实际未授权写入仍返回 `401`。前端仍接受旧服务的 `401` 探测响应。

写入请求同时校验 Host / Origin 策略、内存会话和 `X-Travel-Token`。local 模式只接受回环来源及本机 Host；remote 模式只接受配置的完整 HTTPS Origin 和对应 Host，不依赖 `X-Forwarded-*`。首次设密仅限 local 模式本机页面。认证配置保存随机盐与 scrypt 哈希，Cookie 为 `HttpOnly`、`SameSite=Strict`，remote 模式增加 `Secure`。详细部署限制见 [维护指南](MAINTENANCE.md#认证与部署边界)。

记录新增与修改使用 `application/zip` 提交草稿、原始媒体及修改快照，媒体不再转成整段 Base64 JSON；服务端保留旧 `application/json` 接口。删除仍使用 JSON。大型上传完成后重新核对当前认证配置与会话，拒绝上传期间已注销或失效的凭据。请求先流式落盘，ZIP 目录、媒体大小和文件头校验通过后进入原有写入事务；媒体写入时同步校验 CRC32，失败清理新文件且不提交索引，修改快照比较与重试行为保持一致。

所有数据操作共用根目录 `.travel-data.lock`，锁内重读磁盘索引。新增独占创建正文，媒体写入完成后通过临时索引与 rename 提交；修改、删除先暂存原正文，失败时回滚。浏览器更新附带原始元数据与正文快照，在锁内比较，发生外部变更返回 409；同内容重试仍可识别为已保存。路径拒绝穿越、符号链接和 junction，媒体按实际签名识别。

修改请求的布尔选项 `syncMediaFiles` 默认开启，JSON 与 ZIP 均支持，编辑器提供默认勾选的开关。保存前比较原媒体与准备提交的目录和列表，涉及移除或搬移时先确认真实文件删除风险；警告提供去重后的待删除路径和原文件查看链接，排除其他记录仍引用的文件，并注明移动目标；取消保留草稿，不开始能力探测、打包或上传。开启时按保存后的全量索引检查原记录媒体，暂存不再被引用的旧文件，提交成功后删除暂存文件并逐级清理空目录（保留照片和视频根目录），失败时恢复；目录未变化时移除的媒体也按此处理。原媒体列表已为空时仍清理已存在的空目录；编辑器保存前重新探测 `syncMediaFiles` 能力，未声明支持的旧服务会中止保存并提示重启。关闭时只更新已有媒体引用，不搬移或删除原文件，新上传媒体仍正常写入。该选项不写入旅行索引，整篇日记的删除仍保留媒体文件。

编辑器按图片、视频分别统一排列已有引用与新增文件，支持多选后批量前移、后移和移除。草稿及 ZIP 的可选 `mediaOrder.photos` / `mediaOrder.videos` 记录各类型「已有引用后接新增媒体」的完整索引排列，缺省沿用旧顺序；读取时校验排列完整、不重复且不越界。服务端分离文件名分配与展示顺序，搬运和写入按原始来源对应目标名，索引按用户排列保存，重试按同一排列核对字节。保存自定义混合顺序前检查写入服务声明的 `mediaOrder` 能力，旧服务提示重启并保留草稿。

完整备份包含 `data/` 与有效 `.secrets/auth.json`。网页导入先确认覆盖风险，再强制验证当前密码、选择并核对备份，然后验证备份密码（不含认证配置的旧备份保留当前密码）；服务端在写入前校验备份密码，密码失败独立限速。导入先校验 ZIP 目录、范围、头信息、CRC32、路径、字段及正文，再暂存和替换；含认证文件时恢复备份密码，旧备份缺少时保留当前密码，成功后注销旧会话。网页与命令行导出以 ZIP64 流逐文件读取，网络或磁盘背压传递到读取端；导入使用磁盘字节源随机访问中央目录，正文逐篇校验，媒体边解包边校验。文本及中央目录各限制 16 MiB，文件数最多 50000，避免恶意清单占用大量内存。ZIP64 头部、扩展字段和数据描述符采用 [PKWARE ZIP 格式规范](https://pkware.cachefly.net/webdocs/casestudies/APPNOTE.TXT)。ZIP / ZIP64 只支持未压缩存储格式，拒绝分卷、加密和不一致目录。

多个文件的操作不能保证断电时的跨文件事务。进程强制结束可能遗留上传临时文件、锁、正文或备份目录，恢复时须先停服务并成对核对数据和认证配置。保存成功但前端重读失败会单独提示，避免误认为没有写入。

## 耗时操作进度

完整备份、草稿、媒体选择及记录保存、头像处理和媒体下载统一使用视口右下方的纸面悬浮进度层，不占用页面或弹窗布局。原生 dialog 打开时，进度层挂在该 dialog 下并通过 Popover API 进入顶层，保持可见及可交互。文件扫描与传输显示真实的字节数或文件数量；无法测量总量、图片转换、服务器校验写入及刷新阶段显示不定进度，不用计时器模拟百分比。上传请求使用原生 XHR，上传完成后继续等待服务端成功响应；失败保留错误并允许重试。进度提示支持读屏播报与减少动态效果设置。

进度浮层提供取消操作：读取和打包在异步边界停止，上传中止 XHR，下载通过 AbortSignal 中止网络并放弃未完成的文件写入。取消后保留编辑草稿并恢复控件，不显示为失败或完成。上传结束进入服务端校验、写入或恢复后禁用取消；清空数据及提交后的刷新阶段也不可取消，避免将已经提交的数据误报为撤销。

创建进度对象时不显示浮层，首次进入实际处理阶段或收到进度更新时才挂载。风险确认、权限探测、密码输入、备份目录预检与文件核对、下载保存位置选择等准备步骤不显示进度；备份在最终确认并提交后才显示上传及恢复进度。备份密码失败返回密码窗口重试时移除本次上传浮层，错误由密码窗口提示。

媒体查看器的更多控制中提供原图片、原视频下载。支持 `showSaveFilePicker` 时将响应按块直接写盘；不支持或缺少用户激活时，最多缓存 256 MiB，超过上限则交给浏览器原生下载，并明确提示在下载列表查看进度或取消。网页只能确认数据传输或直接写盘完成，不能观测浏览器下载列表的最终落盘结果。

## 扩展原则

优先提取可独立测试的解析、统计和校验逻辑，保持单一数据来源与明确模块职责。新逻辑复用既有原生模块、对话框和样式；不为局部改善引入框架、运行时依赖或复杂抽象。
