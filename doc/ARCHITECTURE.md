# 架构说明

## 运行入口与页面

前端为原生 ES modules，入口是 `index.html`、`js/app.js` 和 `css/journal.css`。浏览不依赖 Node API；可选 `js/server.js` 提供静态资源、认证、记录写入和完整备份。项目没有运行时 npm 依赖，也不需要前端构建。

| Hash 路由 | 页面与职责 |
| --- | --- |
| `#cover` | 合盖封面与开本入口。 |
| `#preface` | 扉页、个人资料、日记工具箱、备份及访问安全；`panel=recycle` 定位回收站，`panel=media` 定位媒体整理，`panel=delete` 定位批量删除日记，支持刷新与历史返回。 |
| `#ledger` | 日记目录，支持按笔记或行程查看、搜索和多级筛选；`view=notes` / `view=trips` 明确指定分类，无参数时恢复上次选择。 |
| `#archive` | 日记归档及地点统计。 |
| `#place?country=CN&area=...` | 地点档案、相关日记及汇总媒体预览，参数按 URL 编码。 |
| `#trip`、`#trip?id=...` | 无 `id` 时兼容跳转到日记目录的行程视图；有 `id` 时提供行程摘要、沿途日记列表、汇总媒体预览、相邻行程切换和整趟导出；`id` 为按 URL 编码的行程键。 |
| `#entry?id=...` | 日记详情、相邻篇目与记录管理；`from=recycle`、`from=media` 和 `from=delete` 保留回收站、媒体整理或批量删除来源，刷新或新标签打开后仍提供对应的返回入口。批量删除列表通过标题链接阅读日记，返回时恢复搜索、勾选、焦点与滚动位置。 |
| `#photos?id=...` | 当前日记的图片、视频附件。 |
| `#photos?trip=...` | 对应行程全部日记的图片、视频附件，按日记日期和标题分组。 |
| `#photos?country=CN&area=...` | 对应地点全部日记的图片、视频附件，按日记日期和标题分组，可附加 `locality` 限定目的地。 |

筛选与页面状态由 `app.js` 统一管理，旧 `province` / `city` 参数会转换为当前地点模型。不存在的记录、空列表、正文缺失和加载失败各自呈现可恢复状态；加载失败解除封面模式，使错误和重试入口可见。

媒体附件页的左页提供统一的媒体概览，覆盖单篇日记、行程及地点汇总。数量、类型占比、所属日记、记录日期范围和地点数均基于右页实际列出的附件；多篇汇总提供平均附件数及媒体最多日记的链接。日期采用所属日记日期，不额外读取原文件元数据。概览使用原生 `details`，桌面默认展开、不超过 760px 默认收起；跨越断点重设默认状态，同一布局内保留手动开关。

完整媒体列表超过 60 项时由 `photo-sleeve-virtual.mjs` 按行虚拟滚动，只挂载视口及前后一屏的标题和媒体行。桌面监听右页独立滚动，手机监听窗口滚动；列宽、字体变化后重新测量按钮和分组标题，保留完整滚动高度。查看器直接读取全量媒体数据，原始索引、跨窗口切换与 Tab 顺序保持一致。卸载虚拟行和切页时清理观察器及缩略图引用。

目录分类使用浏览器本地存储记忆，存储受限时回退到本次浏览状态；规范路由显式保留分类，使历史记录可准确恢复。目录中的行程路线超过三个途经点时只显示起点、省略号和终点。行程详情复用地点档案的 `place-page`、`place-summary`、`place-records`、地点标签、媒体预览和相邻项样式；左页汇总日期、真实行程 ID、日记及媒体数量，右页按日期从早到晚列出日记，打开后沿用日记详情的来源返回。目的地按地点标识去重，点击进入地点档案。相邻行程按最早日记日期排序，纸面导航与快捷翻页保持一致；返回目录明确打开按行程视图。手机沿用地点详情的连续纸面，依次展示摘要、沿途日记、媒体预览与相邻行程。行程媒体附件页复用地点媒体页的分组展示与查看器。

## 读取与浏览器交互

署名与档案独立并行加载；索引先校验，重复的固定标识或旧版正文身份在生成路由前报错，防止日记链接指向错误记录。正文最多 8 个请求并发，单次请求超时为 20 秒。同轮加载共享相同路径的正文请求，每条记录独立解析，刷新时重新请求。正文允许浏览器缓存，结果保持索引顺序；404 等永久性响应及超时不立即重试，临时服务端错误和响应中断允许重试一次。单篇失败显示提示并保留其他记录及地点搜索，不让一篇文件拖垮全站。署名读取失败回退默认值，头像从 `data-src` 加载。封面图片由可见封面的 CSS 背景触发加载，不做全路由预加载，避免直接打开日记或扉页时出现未使用预加载资源的警告。

Markdown 使用应用支持的有限语法，输出经过 HTML 转义与链接过滤；预览复用相同解析器，编辑后通过受限 DOM 序列化生成 Markdown。新增格式必须同步考虑展示、编辑与安全过滤。

桌面采用双页分工及独立滚动；不超过 760px 时转为连续阅读，路径筛选、扉页工具箱和归档概览使用可开关夹层。长连续文字允许换行，窄屏及触摸设备放大控件点击范围，短横屏压缩媒体工具间距。夹层和媒体查看器锁定背景交互、约束 Tab 焦点，关闭查看器恢复触发按钮焦点。跳转链接聚焦内容区；修饰键点击路由链接保留浏览器原生行为。

自定义选择框以原生 `select` 为数据来源，同步禁用状态并跳过禁用选项；方向键及 Home / End 可导航，菜单按可见视口限制尺寸。菜单关闭后停止布局更新。

搜索更新保留原输入、光标与选区，Tab 离开后保持当前控件焦点；点击筛选同时纳入尚未到防抖期限的搜索内容，重绘后聚焦可见筛选按钮。无结果时提供清除条件的恢复入口。原生对话框打开时，媒体与夹层快捷键暂停；丢失指针捕获或窗口失焦会中止拖动，避免进度条保持在拖动状态。

连续导航时，正在播放的翻页保留当前曲面，以最多 160ms 加速落稳后衔接最新目标；落页期间的重复请求只保留最后一次。首帧播放前可直接替换，关闭或禁用动画时立即清理副本与回调，窗口尺寸变化时直接呈现待切换目标。启用 `prefers-reduced-motion` 时直接切换，动画期间背景内容使用 `inert` 防止穿透操作。

纸张破损使用 SVG 边框纹理，包含缺口、磨损暗边与浅色纤维，固定为 12px 宽并沿长边平铺。桌面静态装饰绘在独立伪元素上，仅此平面装饰层按纸页圆角限制范围，保留完整书脊；翻页副本直接在自身外框绘制边框，避免纹理随正文滚动或被滚动条槽挤向页内。手机在整张连续纸面的外沿绘制一圈，详情页以左右各 5px 的内边距替代原来的实线边框，保持内容占位并让装饰定位框与纸面外沿一致。翻页继续使用原来的曲面、纸背和光影实现，禁止给纸面、曲面容器或其祖先新增 clip-path 或 mask，避免干扰三维合成并增加重复裁绘的开销。

动画准备期间保留平面旧页覆盖，等待目标纸面背景、首屏可见图片解码和字体就绪后再生成目标副本，完成首帧绘制后交接曲面纸带；取消时一并清理资源等待与副本。可见附件尚未设置 `src` 时主动启动预览，与懒加载观察器共用同一读取和解码任务；手机详情页的 `display: contents` 纸页按视口判断子元素，屏外附件继续懒加载。资源失败或等待超过 2 秒时直接切换真实页面，避免动画中途补画或阻塞导航。桌面副本固定原页背景、内边距并沿用自定义滚动条槽宽，避免新路由样式或滚动条类型变化导致内容跳动。动画副本在深拷贝前裁去屏外记录内容，附件网格固定原尺寸且只保留可见子项；可见图片和视频冻结为最长边不超过 512px 的静态缩略图，避免每条卷曲纸带重复创建视频解码器或绘制原始大图。未解码或无法读取的媒体在动画中保留占位。预览行数同步及尺寸观察仅作用于真实左右页，跳过动画副本。

扉页头像与附件共用翻页静态快照，避免副本复制已经释放的 Blob 地址。尚未显示的头像按相框位置判断可见性，并等待读取和解码；开书也执行相同的资源等待，取消时释放等待回调，缺省头像继续保留原有纸面占位。

附件列表、编辑器、确认列表和头像统一读取 `.cache/media-previews/` 中最长边不超过 640px 的 JPEG 预览，视频使用首帧封面。保留原扩展名避免重名；仅在进入视口后读取，同一路径共享请求，最多同时处理两项。所有缩略图共用可见性观察器，隐藏、折叠及滚动容器外的项目不读取；头像观察相框，本地待上传附件也在显示时才生成和设置缩略图。不支持 IntersectionObserver 时通过滚动、尺寸及 DOM 变化检测可见性。队列开始读取前再次检查，已移除或离开可见区域的项目跳过，重新显示后恢复读取。

已读取的缩略图 Blob 与 URL 保留在当前页面会话的内存缓存，切页、筛选和重新打开列表时复用，不重复请求；缓存最多保留 256 项、合计 32 MiB，超限按最近使用顺序淘汰。记录、媒体、备份、回收站或头像写入后清空内存缓存，刷新页面后重新校验服务器版本。缓存命中时只读取缩略图；缺失时读取一次原文件，压缩后写入缓存。回收站预览按不可变的归档 ID 和路径缓存到浏览器 Cache Storage，本地导入文件按可见性压缩；解码失败才保留可点击占位。

缓存淘汰和清空时，正在解码的图片各自保留 URL 引用，最后一个使用者完成加载、失败或卸载后才撤销地址。取消后重新观察的可见缩略图会主动检查可见性；媒体页遇到临时读取或解码失败时延迟重试一次，滚出视口的任务等待再次显示。

原图由 `media-original.mjs` 在查看器打开图片后读取，独立缓存 Blob 与 URL，最多保留 32 张、合计 128 MiB，超限按最近使用顺序淘汰并释放 URL。重复查看和并发打开共享读取结果；数据变更时与缩略图缓存一起清空，清空前的请求不能回填旧缓存。单张超过容量上限或读取失败时沿用原地址显示，本地待上传文件复用编辑器持有的 Blob URL。

`media-preview.mjs` 共用图片、视频的解码、等比缩放、居中裁切和 JPEG 压缩逻辑。编辑器为本地待上传附件生成 320×200 预览，保存成功后按最终附件顺序写入服务器缓存；头像上传同样补齐缩略图。缓存写入失败不影响已保存的原文件，可运行 `npm run media:previews` 补齐已有媒体和头像。批量生成在本机浏览器中读取原文件，普通访客无需重复下载。

Node 服务通过 `media-preview-store.js` 读写 `.cache/media-previews/`，检查源文件指纹、JPEG 格式与尺寸，并提供 ETag 校验；源文件变化后旧缓存失效。静态托管优先读取预生成的相同目录，GitHub Pages 在发布前调用本机 Chrome 生成缩略图。静态站缺失时由浏览器压缩并写入 Cache Storage，通过原文件 HEAD 的 ETag、Last-Modified 和 Content-Length 验证版本。动态服务缺失时生成并同源 PUT 到服务器缓存，源文件变化时拒绝旧预览；缓存不可写时仍显示本次压缩结果。

## 样式结构

`journal.css` 按编号顺序加载 11 个同目录分片，后加载的规则可覆盖前者；CSS 资产统一以 `../assets/` 引用。

| 分片 | 范围 |
| --- | --- |
| `01-foundation`、`02-shell` | 字体、变量、基础可访问性、书脊与纸页外壳。 |
| `03-controls`、`04-ledger`、`05-archive-place` | 共用按钮、日记目录、归档及地点。 |
| `06-entry-sheet`、`07-responsive`、`08-custom-select` | 正文、事务对话框、基础适配和选择菜单。 |
| `09-book-experience`、`10-refined-ui`、`11-skeuomorphic-book` | 开合封面、视觉覆盖、拟物细节和最终屏幕适配。 |

改样式先确认实际生效的覆盖层，延续皮革、纸张、黄铜和手账排版。发布浏览器资源修改时，更新 `package.json` 的版本并执行 [README 中的资源版本同步](../README.md#测试与资源版本)，从入口递归同步模块与样式的版本参数；公共模块不得同时使用带版本和不带版本的 URL，避免重复初始化弹窗和全局事件。不要增加另一套页面入口或平行组件体系。旧首页的近期记录卡片、随机路线票据、旧日记详情弹层及配套动画、样式已移除，`#cover` 只保留实体封面，记录浏览统一从日记目录进入；`entry-sheet` 仍为现有编辑、认证和数据操作对话框提供共用纸面样式。

部分记录导入导出、媒体整理及回收站共用 `management-dialog` 的标题、关闭入口、搜索、文字工具和操作区。选择跨搜索或分类保留，底部明确提示筛选范围外的已选数量；全选只作用于当前筛选中的可选结果，清空选择作用于全部已选项。媒体整理分别保存未使用文件与缺失文件的选择，底部操作只提交当前类别；重新检查保留仍符合对应操作条件的选择，请求失败后禁止操作，重新检查成功才能继续。共用分类不保留选择列，全部现有文件中的已引用文件显示禁用选择框。回收站搜索仅筛选显示，清空回收站始终作用于全部回收项目，确认框明确列出总数。

回收站在常规高度下统一滚动内容列表，搜索区和恢复操作区持续可见。短屏切回整张纸面滚动。日记分组与逻辑目录保持红色链接及默认折叠，折叠后仍显示已选数量。归档内容和恢复预览共用目录压扁逻辑，仅有一个分类子目录时直接展示其内容。日记、个人资料选择行与共用内容归属行保留，多分类仍分层，空日记仍可显示信息与选择入口。选中记录显示恢复范围和预览状态，按日记选择区提供 44px 触控范围，键盘焦点沿用印章红。跳转阅读时分别保存内容列表和纸面滚动位置，返回后恢复。

含 `data/travel_data.json` 的回收批次提供独立的日记索引勾选入口，恢复时整份替换索引，回退全部日记元数据和附件引用。同批次可同时勾选日记文件及个人资料，索引与所选文件共用回滚范围；跨批次沿用整份索引的独占恢复校验。预览按实际写入范围展示正文与媒体变化，索引移除日记仅展示元数据移除，恢复成功后丢弃被替换的当前内容，原批次继续保留。编号元数据差异按基本信息、图片列表、视频列表和附件顺序分组，组间增加标题、留白与分隔线，双侧行号按完整元数据序列连续计算。

`zip-stream.mjs` 使用不带查询参数的唯一规范 URL：它的 `ByteSource` 类由 Node 文件流、草稿和备份模块共同使用，必须保持同一类身份。版本同步脚本会统一移除此模块的查询参数，其余浏览器模块与样式使用当前发布版本。

## 认证与写入

日记工具箱的部分记录导入、导出与其他管理入口一致：进入文件选择器或记录选择界面前探测当前服务端会话，有效时直接继续，未登录或过期时才验证当前访问密码。同一浏览器会话内最长 8 小时免重复验证，刷新页面后仍可复用；每次探测不会延长有效期。取消选择文件只清除本轮导入凭据，不注销登录会话。密码明文不写入浏览器存储。

单篇删除、清空数据、导入全部数据及切换记录丢弃未保存内容时，点击入口先确认危险操作，之后才探测服务、验证密码或选择文件。取消确认不会清除草稿或执行后续操作。

| API | 用途 |
| --- | --- |
| `/api/travel-auth`、`/api/travel-auth/setup` | 登录、换密、首次本机设密。 |
| `/api/travel-records` | 能力探测、创建、更新与删除。 |
| `/api/travel-profile` | 头像与署名写入。 |
| `/api/travel-data` | 完整备份导入导出与清空；`POST ?mode=select` 准备会话内部分导出选择，`GET ?selection=...` 下载，`POST ?mode=merge` 合并记录；`POST ?mode=verify-backup` 用不超过 4 KiB 的认证配置预校验当前和备份密码。 |

前端通过同源相对 URL 探测能力。静态发布物的 `api/travel-records` 提供 `travel-diary-static-v1` 标记，只有明确标记才打开免密码只读编辑器；404、超时、403 和异常响应均中止操作。动态能力 GET 在未登录或会话失效时返回 `200`、`authenticated: false`、空 `methods` 和 `AUTH_REQUIRED`，不泄露 token；正常打开密码窗口不会产生 `401` 控制台报错，实际未授权写入仍返回 `401`。前端仍接受旧服务的 `401` 探测响应。

写入请求同时校验 Host / Origin 策略、内存会话和 `X-Travel-Token`。local 模式只接受回环来源及本机 Host；remote 模式只接受配置的完整 HTTPS Origin 和对应 Host，不依赖 `X-Forwarded-*`。首次设密仅限 local 模式本机页面。认证配置保存随机盐与 scrypt 哈希，Cookie 为 `HttpOnly`、`SameSite=Strict`，remote 模式增加 `Secure`。详细部署限制见 [维护指南](MAINTENANCE.md#认证与部署边界)。

记录新增与修改使用 `application/zip` 提交草稿、原始媒体及修改快照，媒体不再转成整段 Base64 JSON；服务端保留旧 `application/json` 接口。删除仍使用 JSON，单篇提交 `desc_md`，批量提交无重复的 `paths` 和选取时的 `expectedRecords`。批量删除先验证密码、选择日记并确认数量，在同一数据锁与回滚范围内提交，各篇分别留存在回收站。JSON 与 ZIP 请求在读取完成后、取得数据锁时及提交前重新核对当前认证配置与会话，记录与个人资料上传期间已注销、换密或失效的凭据不能继续写入；失败沿用原事务回滚。请求先流式落盘，ZIP 目录、媒体大小和文件头校验通过后进入原有写入事务；媒体写入时同步校验 CRC32，失败清理新文件且不提交索引，修改快照比较与重试行为保持一致。

所有数据操作共用根目录 `.travel-data.lock`，锁内重读磁盘索引。新增独占创建正文，媒体写入完成后通过临时索引与 rename 提交；修改、删除先暂存原正文，失败时回滚。浏览器更新附带原始元数据与正文快照，在锁内比较，发生外部变更返回 409；同内容重试仍可识别为已保存。路径拒绝穿越、符号链接和 junction，媒体按实际签名识别。静态读取同时校验请求路径与真实路径，拒绝隐藏文件、备份与运行目录，避免绕过认证 API 下载完整备份；认证配置仅保存本机，不进入 Git。

修改请求的布尔选项 `syncMediaFiles` 默认开启，JSON 与 ZIP 均支持，编辑器提供默认勾选的开关。保存前比较原媒体与准备提交的目录和列表，涉及移除或搬移时先确认真实文件删除风险；警告提供去重后的待删除路径和原文件查看链接，排除其他记录仍引用的文件，并注明移动目标；取消保留草稿，不开始能力探测、打包或上传。开启时按保存后的全量索引检查原记录媒体，暂存不再被引用的旧文件，提交前将暂存文件复制到统一回收站，提交成功后清理暂存并逐级清理空目录（保留照片和视频根目录），失败时恢复；目录未变化时移除的媒体也按此处理。原媒体列表已为空时仍清理已存在的空目录；编辑器保存前重新探测 `syncMediaFiles` 能力，未声明支持的旧服务会中止保存并提示重启。关闭时只更新已有媒体引用，不搬移或删除原文件，新上传媒体仍正常写入。该选项不写入旅行索引，整篇日记的删除将记录与文件留存到回收站，原位置仅保留仍被其他日记引用的媒体。

编辑器统一排列图片、视频的已有引用与新增文件，支持多选后批量前移、后移和移除。草稿及 ZIP 的可选 `mediaOrder.photos` / `mediaOrder.videos` 记录各类型「已有引用后接新增媒体」的完整索引排列，缺省沿用旧顺序；读取时校验排列完整、不重复且不越界。服务端分离文件名分配与展示顺序，搬运和写入按原始来源对应目标名，索引按用户排列保存，重试按同一排列核对字节。可选 `mediaOrder.sequence` 按 `photo` / `video` 记录跨类型顺序，校验数量与类型完整；保存为记录的 `media_order`（`类型:文件名` 数组），编辑器和相册均按它排列，失效引用跳过，新附件追加，旧记录沿用图片后接视频。拍摄时间排序对全部媒体执行一次统一排序，取消时不改变顺序。保存自定义新旧顺序前检查写入服务声明的 `mediaOrder` 能力，图片视频统一排序另检查 `mixedMediaOrder` 能力，旧服务提示重启并保留草稿。

完整备份包含 `data/` 与有效 `.secrets/auth.json`。网页导入先确认覆盖风险，再复用有效会话或验证当前密码、选择并核对备份，然后验证备份密码（不含认证配置的旧备份保留当前密码）；已登录且备份的盐和哈希与当前配置一致时可复用认证，否则仍需备份密码。服务端在写入前校验备份访问权限，显式提供的错误密码仍会拒绝，密码失败独立限速。导入先校验 ZIP 目录、范围、头信息、CRC32、路径、字段及正文，再暂存和替换；含认证文件时恢复备份密码，旧备份缺少时保留当前密码，成功后注销旧会话。网页与命令行导出以 ZIP64 流逐文件读取，网络或磁盘背压传递到读取端；导入使用磁盘字节源随机访问中央目录，正文逐篇校验，媒体边解包边校验。文本及中央目录各限制 16 MiB，文件数最多 50000，避免恶意清单占用大量内存。ZIP64 头部、扩展字段和数据描述符采用 [PKWARE ZIP 格式规范](https://pkware.cachefly.net/webdocs/casestudies/APPNOTE.TXT)。ZIP / ZIP64 只支持未压缩存储格式，拒绝分卷、加密和不一致目录。完整导入及部分合并共用跨平台大小写和文件目录冲突校验；内存与磁盘字节源使用相同的安全整数及切片边界约束，允许末尾空切片。

多个文件的操作不能保证断电时的跨文件事务。进程强制结束可能遗留上传临时文件、锁、正文或备份目录，恢复时须先停服务并成对核对数据和认证配置。保存成功但前端重读失败会单独提示，避免误认为没有写入。

部分备份包含 `data/record-backup.json` 格式标识、按日期倒序筛选的 `data/travel_data.json`、正文、去重媒体和 `.secrets/auth.json`，不包含个人资料。前端从完整或部分备份导入时，使用 Blob 切片与分块 CRC 校验重新封装所选内容，保留认证配置用于备份密码验证。完整和部分导入共用 `backup-password.js`：先验证当前密码，再通过有会话和令牌保护的预校验接口尝试同一密码，仅在 `BACKUP_PASSWORD_INVALID` 时追加询问备份密码；全部验证后才整理、上传大文件。预校验与正式导入共用独立失败限速，客户端提供的配置即使校验成功也不清除失败计数，正式导入仍验证 ZIP 内的认证配置，防止预校验成为绕过入口。旧备份不含认证配置时保留兼容行为。

部分导入在锁内比较所选记录，只将实际变化且已有匹配的旧记录及其正文、附件保存为 `record` 回收批次，不保存完整索引或未选内容。新增和相同记录不留存；恢复按固定标识合并回当前索引，保留其他记录的后续修改。整站导入仍使用 `snapshot`，安装失败时两种留存都会撤销。

服务端仅在显式 `merge` 模式接受部分备份；优先按 `record_id`、兼容旧记录派生身份及正文路径合并索引，仅安装所选记录引用的文件。未选记录共用的同路径媒体有不同内容时返回 409。合并结果与现有文件一起检查大小写及文件目录冲突，沿用数据锁和完整暂存目录切换事务，保留现有认证及会话。部分导出的选择保存在当前会话的有界 Map 中，最多保留最近 8 次，避免大量记录路径塞入 URL，并兼容大文件由浏览器原生下载接管。能力探测通过 `partialRecords` 声明支持，前端拒绝旧服务。

## 耗时操作进度

完整备份、草稿、媒体选择及记录保存、头像处理和媒体下载统一使用视口右下方的纸面悬浮进度层，不占用页面或弹窗布局。原生 dialog 打开时，进度层挂在该 dialog 下并通过 Popover API 进入顶层，保持可见及可交互。文件扫描与传输显示真实的字节数或文件数量；无法测量总量、图片转换、服务器校验写入及刷新阶段显示不定进度，不用计时器模拟百分比。上传请求使用原生 XHR，上传完成后继续等待服务端成功响应。Fetch 降级路径在收到响应头后切换服务端处理阶段，断网和总时限监测持续到响应体读取完成。零状态、响应中断及无效 JSON 均提示结果尚未确认，完整导入与头像上传保留该提示，恢复连接后先核对再重试。认证及备份密码预校验共用响应读取逻辑，保留服务端错误码，将连接中断、网关错误和无效响应明确反馈到原验证窗口，并恢复输入。进度提示支持读屏播报与减少动态效果设置。

进度浮层提供取消操作：读取和打包在异步边界停止，上传中止 XHR，下载预检通过 AbortSignal 中止请求；浏览器接管后由下载列表管理取消。取消后保留编辑草稿并恢复控件，不显示为失败或完成。上传结束进入服务端校验、写入或恢复后禁用取消；清空数据及提交后的刷新阶段也不可取消，避免将已经提交的数据误报为撤销。

创建进度对象时不显示浮层，首次进入实际处理阶段或收到进度更新时才挂载。风险确认、权限探测、密码输入、备份目录预检与文件核对等准备步骤不显示进度；备份在最终确认并提交后才显示上传及恢复进度。备份密码失败返回密码窗口重试时移除本次上传浮层，错误由密码窗口提示。

媒体查看器的更多控制中提供原图片、原视频下载。所有 URL 下载统一先发送 HEAD 预检文件可用性及权限，通过后以下载链接交给浏览器接收正文和保存，保留文件名及查询参数。下载准备失败或取消时不发起下载。网页不读取下载正文，也不创建 File System Access 写入流。

完整、部分记录及行程备份无论大小均使用浏览器原生下载，由下载列表管理保存位置、进度和取消。预检仅返回响应头，备份基准在正文传输成功后更新。本地草稿完成打包后、媒体查看器持有本地 Blob 时，通过临时对象 URL 交给相同的浏览器下载入口，延迟释放 URL。

浏览器原生下载接管后显示同款悬浮进度层，显示不定进度及下载列表说明，6 秒后自动收起，也可提前手动关闭。网页无法观测原生下载的百分比或保存结果，提示不自动标记完成，关闭提示仅移除浮层。草稿打包及本地 Blob 下载也使用同一接管提示。

## 扩展原则

优先提取可独立测试的解析、统计和校验逻辑，保持单一数据来源与明确模块职责。新逻辑复用既有原生模块、对话框和样式；不为局部改善引入框架、运行时依赖或复杂抽象。

## 记录变更与媒体管理

新增记录的固定标识由草稿请求标识及初始正文路径派生；旧记录使用 `legacy:` 加原始正文路径，修改时保留。读取和导出可补齐身份但不写原索引，修改及完整或部分导入持久化身份。前端路由使用固定标识，并保留当前正文文件名生成的旧链接别名。

`GET /api/travel-data?mode=inventory` 在数据锁内生成当前记录、文件大小与 CRC32、SHA-256 内容指纹和最近导出状态；此只读接口无需密码，导出与写入仍要求认证。浏览器比较备份目录中的大小和 CRC32，读取所选记录的正文以展示差异；CRC32 用于变化提示，正式导入继续逐文件校验。合并 ZIP 中的 `data/record-merge.json` 携带预览时所选记录的当前指纹（新增为 null），服务端锁内复核，完成后不保存该临时清单。共享文件与独立同名文件的不同内容仍拒绝覆盖。

动态导出返回会话绑定的 `X-Travel-Backup-Receipt`，流传输成功后，在释放数据锁前自动写入此次导出快照的备份比较基准。未选记录保留原基准，失败、中断和 HEAD 请求不推进基准。保留 `POST ?mode=backup-complete` 及 `backupReceipt` 参数供旧页面兼容，并继续验证会话和回执。当前页面统一使用 HEAD 预检与浏览器原生下载，基准保存在本机缓存中。

`GET /api/travel-data?mode=media-health` 扫描普通媒体文件与引用；`POST` 同模式使用 `trash`、`restore`、`purge`、`remove-missing` 操作。操作要求会话和令牌，在共用数据锁内核对体检版本，再执行未引用媒体回收、独占恢复及显式永久清理。`remove-missing` 仅接受当前缺失清单中的路径，从全部关联日记的附件列表中批量移除引用，通过临时索引与 rename 原子提交；前端检查 `mediaReferenceRemoval` 能力，沿用未使用文件的勾选、全选和底部提交流程，成功后刷新日记数据。统一回收站位于 `.cache/recycle-bin/<批次标识>/`，旧 `data/media-trash/` 自动迁移，含原文件及恢复清单；路径逐层拒绝符号链接和 junction。损坏或缺失的回收清单停止清理并提示人工核对，不静默当作空目录。

文件批次明确指定 `targetDescMd` 时，预览和提交共用目标路径规划，将附件复制到目标日记当前的媒体目录并合并列表；同名来源冲突或非法目标路径拒绝。预览返回 `savedFiles` 的目标路径与回收来源映射，前端据此读取缩略图；预览令牌继续绑定目标日记及磁盘状态，所有目标文件和索引共用回滚范围。

回收站 `POST ?mode=recycle-bin` 的 `preview` 操作在数据锁内计算实际恢复结果，复用 `compareBackup` 比较元数据、正文与附件，独立文件及整站移除也纳入差异。`record-diff-view.js` 由部分导入和回收站共同调用，统一渲染行差异和延迟加载附件，来源分别为 ZIP 字节源或已鉴权的回收文件 URL。回收站恢复预览依次展示日记信息、正文与附件，日记信息复用正文的双侧行号、增删标记及差异块样式。预览令牌绑定当前数据、回收内容及目标日记，确认恢复时锁内复核；当前文件与索引临时保留用于失败回滚，恢复成功后清理临时内容。旧调用未携带预览令牌时仍拒绝同名冲突。回收站勾选后串行自动生成各项目预览，默认收起，取消选择或更改目标后丢弃过时响应。`restore-selected` 接收所选项目及各自的预览令牌，在同一数据锁内先校验全部令牌与项目冲突，再合并附件引用，通过一次文件与索引回滚范围提交；整站或包含全量目录的版本需单独恢复，同篇完整记录与其他恢复内容、同路径不同文件版本不能混选。前端通过 `recycleSelection` 能力声明识别支持状态。`purge-selected` 通过 `recyclePurgeSelection` 声明支持，接收非空且无重复的项目标识，在数据锁内复核回收站版本、全部选择及当前日记依赖后才逐项删除，无需恢复预览令牌；未选项目保留。

回收历史的日记分组默认折叠，收起后仍显示已选次数。界面直接在逻辑目录中按整篇日记勾选恢复，不再单独提供内容选择子列。恢复请求的 `parts` 使用 `diary:<正文路径>`，服务端统一展开为该篇归档信息、正文及全部归档附件，共用附件自动去重且仅更新所选日记的引用。整站回收同样支持选择部分日记合并。个人资料通过独立目录勾选，请求的 `parts` 使用 `profile` 展开为归档署名、头像及其他资料文件，可单独恢复或与日记一起恢复。未选日记与个人资料保留当前内容。旧 `record:<正文路径>`、`file:<文件路径>` 请求继续兼容。预览与提交共用范围规划，令牌绑定选择范围，同篇不同版本继续互斥。部分恢复后完整原批次保留，永久清除仍通过整个回收项目的勾选执行。`recycleParts` 与 `batchDelete` 分别声明部分恢复及批量删除能力。目录中现存日记链接到当前日记，已删除日记有归档正文时可在新标签页查看归档原文。扉页“日记与媒体整理”使用统一工具按钮提供批量删除入口。
